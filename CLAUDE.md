## Commands

```
npm run dev                              # dev server
npm run build                            # production build (also type-checks)
npm run lint
npm run covers                           # regenerate covers from design/manifest.json (after changing design/)
npm test                                 # node --test, no framework
node --test src/lib/booking.test.ts      # single test file
```

Env vars are listed in `.env.example`; all are optional locally. Without `DATABASE_URL`, `/book` validates but refuses to save. The DB schema is plain SQL in `db/schema.sql` (no ORM yet).

Next.js 16 with `cacheComponents` enabled: read `node_modules/next/dist/docs/` before using unfamiliar APIs (see `AGENTS.md`). `next/font` options must be object literals (no spreads); the site and design-tile fonts are declared in `src/app/fonts.ts`. Tailwind v4: tokens are `@theme` colors in `src/app/globals.css` (`bg-teal`, `text-muted`, …); shared classes (`wrap`, `eyebrow`, `h-section`, `field`, `label`) are `@utility` blocks, and `@apply` can only reference `@utility` classes.

Tests run under plain Node with type stripping, so any module a test imports (and that module's imports) must use explicit `.ts` import extensions and erasable-only TS syntax (no enums, no `@/` aliases). `tsconfig` sets `allowImportingTsExtensions` for this.

## What Kumbida is

An RSVP service for celebrations (weddings, birthdays, baptisms, debuts, anniversaries, reunions), sold in the Philippines. Three roles, one Next.js app:

- **Admin** (`/admin`, email+password, invite-only, no public sign-up): creates every event, verifies payments, manages bookings/templates/settings.
- **Host** (`/h/<token>`, no account, optional PIN): edits content, photos, RSVP settings, guest list; views/downloads responses. Everything except the **Pay** step is locked until the admin confirms payment.
- **Guest** (`/<slug>`, `/<slug>/i/<short-token>` for personal invites): views the page and RSVPs.

Public marketing site at `/`, booking form at `/book` (creates a `KB-####` booking request, never an event), demo pages at `/demo/<template>/<type>`.

## Stack and hard constraints (§12)

Next.js App Router + TypeScript, deployed to **Cloudflare Workers via OpenNext**, **Neon Postgres** (serverless driver), **Cloudflare R2** for files, Turnstile for bot protection. Drizzle is the recommended ORM. Goal is ₱0/month until there are paying clients.

- Server code must run in the Workers runtime: no native Node modules (no `sharp`), keep per-request CPU low (10 ms free tier).
- **Heavy work happens in the browser:** photo resizing to WebP variants (480/960/1600, EXIF stripped, HEIC decoded client-side), share card rendering (canvas → 1200×630 JPEG), QR codes, receipt OCR (Tesseract.js, loaded only on the Pay step), perceptual image hashes. Uploads go directly to R2 via short-lived signed URLs.
- All storage access goes through one small storage module (upload URL, delete, public URL). The DB stores R2 object keys, never full URLs. Key layout: `events/<eventId>/<photoId>/<width>.webp`, `events/<eventId>/share/<version>.jpg`.
- Guest pages are server-rendered and **cached**, revalidated only on event change. The scheduled job (Cron Triggers) that flips time-based statuses must also revalidate.

## Core architecture

- **Templates are code** (§9): `templates/<name>/` exports metadata (supported event types, `library` | `private` visibility, capabilities such as photo limits), a page component taking a read-only typed `EventView`, and an optional share-card renderer. Templates must render correctly with missing optional data, long names, and 1–5 schedule parts.
- **The RSVP form is shared**, not per-template. Templates only theme it via CSS variables/props, so RSVP behavior never differs between designs.
- **Package gating** (§5.4): six tiers (`starter`, `basic`, `lite`, `standard`, `premium`, `personalized`) decide the features each event gets, enforced by the system. The effective limit is `min(package, template)`. Prices live in config/settings, not code. Downgrades hide data, they don't delete it.
- **Event lifecycle** (§5.5): `draft → published → rsvp_closed → past → archived`. Archiving purges guest personal data (~90 days after the event).
- **RSVP modes**: `none` (Starter: show a contact block instead), `open` (dedupe by mobile number, keep history), `guest_list` (invitations with reserved seats, name search with a last-4-digit mobile check, personal tokenized links).
- **Payments** (§5.6), the most intricate area. No gateway. Orders hold one or more receipts. The InstaPay reference is normalized and matched on its **last 6 digits** against UnionBank. It is unique only together with amount + date: same ref+amount+date on another order is a hard block, anything else only raises a flag. Suspicious-receipt flags are advisory, never shown to the client, with thresholds in config. Nothing becomes `paid` until the admin confirms. Store OCR-read values next to submitted values.
- **Change history**: every host/admin save records old → new and who made it, and the admin can restore.

## Anti-goals (§2): check every feature against these

1. A guest page never looks broken or off-brand, whatever the host enters or uploads.
2. Guest names and phones are visible only to the host and admin. Host tokens are ≥128-bit and stored hashed; pages are `noindex` with no referrer; there are no public guest lists.
3. No RSVP is ever lost.
4. Guest pages must work fast on mobile data and inside the Messenger/Facebook in-app browsers (provide fallbacks, e.g. a Google Calendar link instead of `.ics`).
5. Hosts must never need to message the owner for basic edits.
6. No money mistakes: setup stays locked until payment is confirmed.
7. Templates use original art only: no trademarked characters/brands, no real names/dates/places (use occasion display text and placeholders, §9.1).
8. No running costs before there are paying clients.

## UI conventions (§6.6)

Site and system screens (not invitation templates, which keep their own palette and fonts): cream `#F5F2E9` background, teal `#356B68` primary, deep teal `#294B49` text and dark panels, soft gold `#C5A66B` (never small text on cream), mist green `#D7E0D9`. Fonts: Fraunces (headings) + Nunito (body). Mobile-first, ≥44 px touch targets, WCAG AA contrast. Disabled submit buttons always list what's missing ("To submit, please: …"). The designs gallery tile and preview modal are a single shared component, used on the landing page, the booking page and admin Templates.

v1 UI text is English. The default time zone is Asia/Manila.
